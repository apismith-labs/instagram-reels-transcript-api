## Highlights

The v0.9.0 Go examples expand the reusable client and CLI coverage to Native Bulk, Profile post
metadata, CSV Batch, and journal-backed recovery for Single URL and Native Bulk. The Go module
continues to support Single URL transcription and is tested with Go 1.22.

“Full Feature Parity” describes the Go modes implemented in this repository. It does not mean
that every Python or Node.js capability, Actor feature, or operational scenario is available in Go.

## What's New

- `transcriptapi.Client` exposes `GetTranscript`, `GetTranscripts`, `GetProfilePosts`, and
  `GetTranscriptsFromCSV`.
- Native Bulk submits multiple validated URLs in one Actor Run and reports per-input attribution,
  status, counts, extra results, and Dataset completeness.
- Profile collects post metadata; it does not create transcripts.
- CSV Batch validates the entire file and plans by default. Passing `--execute` explicitly opts in
  to one independent, serial Actor Run per non-empty row.
- Single URL and Native Bulk support exact-input, JSONL-Journal-backed Resume. Resume reads the
  existing Run and Dataset; it does not create a replacement Run. Profile and CSV Resume are not
  supported.
- Result files use unique names. The CSV per-Run cap and the arithmetic estimate across planned
  rows are reported separately; the estimate is not a hard total-batch billing limit.

## Go Installation

The Go module path is
`github.com/apismith-labs/instagram-reels-transcript-api/examples/go`; the reusable package is
`github.com/apismith-labs/instagram-reels-transcript-api/examples/go/transcriptapi`.

```sh
go get github.com/apismith-labs/instagram-reels-transcript-api/examples/go@v0.9.0
```

This command is for the v0.9.0 nested-module tag published with the release. The root repository
release tag is `v0.9.0`; the Go module tag is `examples/go/v0.9.0`. Both tags are expected to
identify the same release commit. The v0.9.0 command is available after those tags are published.
The previously published v0.8.0 module remains installable at `@v0.8.0`.

## Safety & Verification

- The client pins and validates Actor Build Number `0.0.50` and Build ID
  `aJLRmMdQapLQRT4sJ` for the controlled configuration.
- A positive per-Run charge cap can be required. It is sent as a Run option and is not a guarantee
  of the final account bill or a total CSV-batch budget.
- Creation requests explicitly disable `restartOnError`, do not follow redirects, and are never
  automatically retried. Ambiguous creation is reported as `creation_unknown` for manual
  reconciliation.
- Journal intent is persisted before Run creation and Run identity is persisted immediately after
  creation. Persistence uncertainty stops further paid work.
- Dataset reads are single-page and bounded. Incomplete reads are reported conservatively.
- Native Bulk prioritizes exact URL attribution and retains unmatched or conflicting items as
  extras/unknown rather than assigning by position.
- CSV dry-run performs input planning without reading the token or creating Runs. CSV execution is
  explicitly opted in with `--execute` and remains serial, one Run per non-empty row.

## Validation

- Go offline suite: 103 test executions passed; formatting, `go vet`, `go build`, and Windows/Linux
  amd64 cross-builds passed.
- GitHub Actions on the release-candidate baseline: Go 1.22 workflow passed; Python and Node.js
  workflows passed all 11 matrix jobs (12 jobs total across the Go and Python/Node workflows).
- A controlled Go Single URL Live acceptance on Build `0.0.50` returned a transcript with 15
  segments. Its recorded `usageTotalUsd` was `$0.0055`.
- A controlled three-URL Native Bulk Live run succeeded with 15, 14, and 12 segments; a subsequent
  Resume returned the same Run and Dataset.
- A one-account Profile Live check (`resultsLimit=1`) returned one post's metadata.
- CSV dry-run planned one row with zero Runs; a separate one-row CSV Live check returned a
  transcript with 15 segments.
- External installation of the v0.8.0 nested Go module, import, and compilation were verified with
  Go 1.27.3. Go 1.22 compatibility is covered by CI, not by that external installation check.

These are controlled, limited checks. They do not establish long-term production reliability or
success for arbitrary inputs. Usage for the v0.9.0 Native Bulk, Profile, and CSV Live Runs was not
independently verified in the local acceptance artifacts.

## Current Limitations

- Single Resume is offline-tested; a dedicated Single Resume Live acceptance was not performed.
- Native Bulk Live coverage is limited to the three tested URLs; arbitrary sizes and mixed failures
  were not validated live.
- Profile Live coverage is limited to one account and one requested post; multi-account attribution
  and generalized pagination were not validated live.
- CSV Live coverage is limited to one row. The CSV aggregate does not expose `datasetComplete`, so
  that field was not independently verified from the CSV result.
- Go Native Bulk uses one Run for multiple URLs; Go CSV uses one independent Run per non-empty row.
- Go does not yet implement Profile Resume, CSV Resume, parallel CSV execution, or every Python
  and Node.js capability.
- Some ambiguous transport or persistence failures require manual investigation; the client does
  not retry Run-creation POSTs automatically.
- `maxTotalChargeUsd` is a per-Run platform option, not an absolute final-bill guarantee or a hard
  combined budget for a CSV batch.

## Upgrade

After the `v0.9.0` root tag and `examples/go/v0.9.0` nested-module tag are published, install or
upgrade the module with:

```sh
go get github.com/apismith-labs/instagram-reels-transcript-api/examples/go@v0.9.0
```

The package import path is
`github.com/apismith-labs/instagram-reels-transcript-api/examples/go/transcriptapi`. For example,
submit two explicit URLs in one Native Bulk Run with a required per-Run cap:

```sh
go run ./cmd/native-bulk --require-charge-cap --max-total-charge-usd 0.10 \
  https://www.instagram.com/reel/first_id/ \
  https://www.instagram.com/reel/second_id/
```

CSV remains a separate Run per non-empty row. Use `--dry-run FILE.csv` to validate and inspect the
plan without reading credentials or creating Runs; `--execute FILE.csv` explicitly enables the
serial paid path. The per-Run cap multiplied by planned rows is an estimate, not a batch billing
ceiling. See the [Go guide](https://github.com/apismith-labs/instagram-reels-transcript-api/blob/main/examples/go/README.md)
for Profile, CSV, and exact-input Resume examples. After publication, the release will be listed at
<https://github.com/apismith-labs/instagram-reels-transcript-api/releases>.
